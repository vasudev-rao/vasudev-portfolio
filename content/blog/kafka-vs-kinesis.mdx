# Kafka vs Kinesis: Architectural Trade-offs

After running both Kafka and Kinesis in production processing 10M+ events/day, here's what actually matters.

## The Question

Your streaming pipeline needs to ingest millions of events. Kafka or Kinesis?

## Kafka

### Pros
- **Throughput:** Handles 1M+ msg/sec per broker
- **Retention:** Unlimited (disk-based)
- **Ecosystem:** Connect, Streams, KSQL
- **Ordering:** Per-partition guarantees

### Cons
- **Operations:** You manage clusters, upgrades, monitoring
- **Cost:** EC2 + EBS + operational overhead
- **Complexity:** ZooKeeper (pre-KRaft), replication config

### When to Use Kafka
- Need > 10M events/day
- Long retention (days/weeks)
- Complex stream processing
- Multi-consumer patterns
- You have Kafka expertise

## Kinesis

### Pros
- **Managed:** AWS handles ops, scaling, patches
- **Integration:** Native AWS services (Lambda, Firehose)
- **Encryption:** At-rest + in-transit by default
- **Simple:** No cluster management

### Cons
- **Throughput:** 1MB/sec per shard limit
- **Retention:** Max 365 days
- **Cost:** Expensive at scale ($0.015/shard-hour)
- **Vendor lock-in:** AWS only

### When to Use Kinesis
- AWS-native architecture
- < 5M events/day
- Want zero ops overhead
- Short retention needs
- Rapid prototyping

## Real Numbers

### Our Kafka Cluster
- **Scale:** 10M events/day
- **Cost:** $800/month (3x r5.large)
- **Ops time:** 4 hours/month
- **Throughput:** Peak 50K msg/sec

### Equivalent Kinesis
- **Scale:** 10M events/day
- **Shards needed:** 20 shards
- **Cost:** $2,160/month
- **Ops time:** 0 hours
- **Throughput:** Limited by shard count

## Decision Framework

**Choose Kafka if:**
- Scale > 10M events/day
- Cost-sensitive at scale
- Need Kafka ecosystem
- Have ops expertise

**Choose Kinesis if:**
- AWS-centric stack
- Scale < 5M events/day
- Zero-ops priority
- Rapid iteration

## Our Choice: Kafka

We chose Kafka because:
1. 2.7x cheaper at our scale
2. Unlimited retention for replay
3. Kafka Streams for processing
4. Team already had expertise

## Migration Path

Started with Kinesis for MVP, migrated to Kafka at 5M events/day when costs justified operational investment.
